Academic Demonstration & OS Simulation Notice

This application is an educational simulation developed specifically for demonstrating Operating Systems CPU Scheduling concepts. It does not connect to any real-world banking network, ATM hardware, or live financial database.

What is Priority Scheduling?

Priority Scheduling is a CPU scheduling algorithm where each process (or in our simulation, each ATM transaction) is assigned a numerical priority. The CPU is allocated to the process with the highest priority currently available in the ready queue.

  • In this system, Priority 1 represents the highest priority, Priority 2 represents medium priority, and Priority 3 represents lowest priority.
  • When multiple transactions are ready at time t, the CPU chooses the one with the lowest numerical priority integer.

Why Use It in an ATM System?

In real banking environments, transactions have different urgency and system resource profiles:

  • High Priority (P1): Fast, security-critical, or high-value transactions such as Balance Inquiries or VIP/Wire Transfers that need swift verification.
  • Medium Priority (P2): Standard customer operations like Mini Statements and routine Cash Withdrawals.
  • Low Priority (P3): Heavy, multi-step operations like Cash Deposits that require hardware counting and validation.

Preemptive vs. Non-Preemptive

Non-Preemptive (Used in this Project): Once an ATM transaction begins execution, it keeps control of the simulated CPU/ATM dispenser until its burst time is completely finished. It cannot be interrupted even if a higher-priority transaction arrives during its execution.

Preemptive: If a transaction with a higher priority arrives while a lower priority transaction is running, the running transaction is interrupted (preempted) and placed back into the ready queue.

FCFS Tie-Breaking & Insertion Order

When two or more transactions in the ready queue share identical priority numbers:

  • The tie is broken using First-Come, First-Served (FCFS) based on Arrival Time (AT). The transaction that arrived earlier executes first.
  • If both Priority and Arrival Time are identical, their original insertion order in the queue is preserved to maintain deterministic execution.

Mathematical Formulas

Turnaround Time (TAT) = Completion Time (CT) − Arrival Time (AT)
Waiting Time (WT) = Turnaround Time (TAT) − Burst Time (BT)
Average WT = (Σ WT of all transactions) / N
Average TAT = (Σ TAT of all transactions) / N

Waiting time is the total duration a transaction spent waiting in the ready queue before completing its service.

Starvation & The Aging Solution

The Starvation Problem: In a high-traffic priority scheduling system, low-priority transactions (e.g., Priority 3) may be delayed indefinitely if high-priority transactions continuously enter the ready queue.

The OS Solution (Aging): Operating systems resolve starvation using Aging, a technique where the priority of waiting processes is gradually increased over time so that every process is guaranteed eventual CPU allocation.
